# 执行计划（开发步骤）

版本：v1（2026-09-18）

## 0. 总体原则

一次只做一个阶段，前一阶段验收通过后再进入下一阶段，不跨阶段并行、不一口气做太多。顺序逻辑：**先有数据（原料）→ 再有工具（手脚）→ 再有编排（大脑）→ 再用评估度量质量 → 再建 UI → 再补次要功能 → 最后部署打磨**。

## 1. 计划表

| 顺序 | 阶段 | 目标 / 交付物 | 需要的技术 | 验收标准 |
|------|------|--------------|-----------|----------|
| 0 | 项目初始化 | 目录结构、docs、devlog、CLAUDE.md | 文档规范 | 目录与文档齐备，计划可执行 |
| 1 | 数据层 | 3-4 品牌冰箱+洗衣机的故障码库、手册 RAG 语料、型号种子数据 | 数据清洗、CSV/JSON、Embedding、向量库 | 故障码可查表、语料可入库检索 |
| 2 | 核心后端服务 | LLM 接入、RAG 检索服务、MCP server（查故障码 / 读铭牌 / 识别现象 / 查安全手册） | Python、FastAPI、LLM API、多模态、OCR、MCP | 每个工具可单独调用并通过测试 |
| 3 | Agent 编排 | LangGraph 诊断状态机 + 诊断 Agent + 安全审查 Agent（三级护栏） | LangGraph、ReAct、多 Agent、状态管理 | 端到端走通一次完整诊断 |
| 4 | 评估体系 | harness + 诊断评估集（标准诊断路径）+ 指标 | pytest、评估脚本、指标统计 | 评估集可复现，正确率/幻觉率/危险告警率可量化 |
| 5 | 前端 UI | 四区域模块 UI（淡蓝）、照片上传、诊断对话流 | React、Tailwind、文件上传 | 可完整提问并展示诊断 + 安全提示 |
| 6 | 次要功能 | 个人家电名单 + 维修历史记录 | 数据库、CRUD、持久化 | 名单与历史可增删查、可回看 |
| 7 | 部署打磨 | Docker 一键部署、README、演示脚本 | Docker、docker-compose | 一键启动、可现场演示 |
| 8 | 扩展（可选） | 扩展到 10 个品牌 | 数据采集 | 覆盖十大品牌 |

## 2. 各阶段前置依赖

- Phase 1 依赖 Phase 0（目录就绪）。
- Phase 2 依赖 Phase 1（数据可供检索）。
- Phase 3 依赖 Phase 2（工具可用）。
- Phase 4 依赖 Phase 3（有 Agent 可评估）。
- Phase 5 依赖 Phase 3（后端可调用；评估可后置）。
- Phase 6 依赖 Phase 3（诊断流程稳定）。
- Phase 7 依赖 Phase 5、6。
- Phase 8 依赖 Phase 7（流程已验证）。

## 3. 里程碑标记

- M1（Phase 1 完成）：数据可查。
- M2（Phase 3 完成）：最小可诊断闭环。
- M3（Phase 4 完成）：质量可度量。
- M4（Phase 7 完成）：可演示的完整产品。
