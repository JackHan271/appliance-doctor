# 设计规范

版本：v1.1（2026-09-18 立项，2026-10-18 对齐实现）

## 1. 三级安全护栏（本项目核心设计）

| 等级 | 定义 | 软件行为 |
|------|------|----------|
| 🟢 绿 | 可安全自修（擦拭门封条、清理内腔、调温度设置、检查门封外观、复位、断电自然化霜等，完全不打开盖板/面板） | 给出详细步骤 |
| 🟡 黄 | 谨慎操作（清理排水孔、疏通排水管、简单拆面板清洁等，需要打开盖板/面板或接触内部部件） | 强制断电 + 警示 + 详细步骤 |
| 🔴 红 | 必须联系专业师傅（高压电、压缩机、制冷剂、主控板、传感器、加热管等） | **只解释原因，不教危险步骤**，建议联系售后 |

判定以诊断结论里**建议的操作**为准：只要建议里出现打开盖板、拆面板或接触内部部件，至少判黄。根因涉及 red 类部件时一律判红，即使结论里顺带提到「先断电自查」也不能降级。

安全审查 Agent 在用户动手前做最后把关：核对是否已断电、是否涉及高压/制冷剂/主控板、是否会导致保修失效。

## 2. 数据 Schema（已实现，与 backend/app/db.py 一致）

### 2.1 个人家电名单（appliances）
- id（主键）
- brand（品牌）
- model（型号）
- category（品类，默认冰箱）
- category_en（英文品类，默认 refrigerator）
- purchase_date（购买日期）
- warranty（保修信息）
- created_at（创建时间）

### 2.2 维修历史记录（repair_history）
- id（主键）
- brand（品牌 + 品类）
- model（型号）
- level（安全等级：green / yellow / red）
- issue（问题摘要）
- detail（诊断结论）
- created_at（诊断时间）

> 照片不落库：只在诊断时实时交给视觉模型，识别出的文字结论进入 detail。

### 2.3 故障码（fault_codes/*.json）
- brand（品牌）
- brand_en（英文品牌名）
- note（整表说明）
- references（来源链接）
- categories（按品类分组）
  - code（故障码，如 E1）
  - meaning（含义）
  - level（对应安全等级）
  - source（来源）

## 3. UI 模块规范

- 四大区域：个人家电名单 / 提问交互区（核心，最大）/ 维修历史记录 / 通用安全手册。
- 主色调：淡蓝色（建议主色 `#E3F2FD` 系，配深蓝 `#1565C0` 强调）。
- 提问交互区承载：文字输入 + 照片上传 + 诊断对话流 + 安全等级标识 + 步骤卡片。
- 安全提示条：诊断结论顶部必须展示绿/黄/红等级色块与对应安全措施。

## 4. 输出规范

- 诊断回答必须含：结论、安全等级、详细步骤（或"联系师傅"建议）、安全措施、引用来源（手册/故障码出处）。
- 范围外/未知型号必须诚实降级（"该型号未收录，建议读铭牌或联系售后"），不得编造。
