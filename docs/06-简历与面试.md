# 简历项目描述 + 面试讲解要点

## 一、简历写法（可直接复制）

**家电医生 —— 基于 LangGraph 的多 Agent 家电故障诊断系统** · 个人项目

**项目背景**：面向家庭用户的家电故障维修场景，针对普通用户缺乏专业知识、网上维修信息碎片化，以及维修操作存在触电/制冷剂/压缩机等安全风险的痛点，构建多 Agent 诊断系统。融合确定性故障码查表、混合检索 RAG 与受控 Agent 工作流，实现从症状描述/照片到安全可控维修建议的闭环，解决通用 LLM 问答幻觉严重、缺乏安全约束的问题。

**核心贡献**：

- **多 Agent 诊断编排**：基于 LangGraph 状态图构建"诊断 Agent → 反问 → 安全审查 Agent"工作流，利用 interrupt/resume 机制实现多轮交互式诊断，信息不足时主动追问、逐步收敛假设空间，解决单轮问答在故障定位中的信息不足问题。
- **三级安全护栏 + 可评估体系**：设计绿/黄/红三级安全分级与独立安全审查 Agent（不受诊断结论影响、可主动升级等级），构建 35 用例评估集与自动化 harness，量化安全等级准确率约 90%、危险漏报率 0，将维修安全从定性口号变为可回归的工程指标。
- **混合检索 RAG 与工具调用**：融合确定性故障码查表（结构化）与 Milvus 向量检索维修手册（非结构化，BGE 本地 embedding），解决通用 RAG 在家电领域召回不准、缺乏证据锚点的问题；工具（查故障码/读铭牌/识别现象/查安全手册）以 MCP 标准协议暴露，DeepSeek 视觉模型实现铭牌识别与故障照片理解。
- **全栈工程化落地**：React + Tailwind 前端、FastAPI 后端、PostgreSQL 持久化、Docker Compose 部署，形成可演示的完整产品闭环。

## 二、面试高频问题与答法

### Q1：为什么用多 Agent，而不是一个 Agent 干完？

答：诊断和安全审查是**两件有利益冲突的事**——诊断 Agent 追求"给出结论"，可能倾向于给可操作的答案；安全审查 Agent 追求"不让人受伤"。把它们拆成两个 Agent，让安全审查**独立复核、不受诊断结论影响**，是安全场景的正确做法。实际效果上，安全审查 Agent 确实多次把诊断 Agent 的结论**升级**了安全等级（比如诊断判 yellow，安全审查因涉及拆机升级或补充断电警示）。

### Q2：多轮诊断为什么用 LangGraph 的 interrupt，而不是在 FastAPI 层做循环？

答：interrupt 是 LangGraph 官方的"图内中断"机制，它把"暂停→等用户输入→恢复"作为**图状态机的一等公民**，配合 checkpointer 持久化状态。相比应用层拼循环，它的优势是：状态由框架管理、可恢复、可回放，图的边和条件跳转清晰表达了"诊断→反问→再诊断→安全审查"的流程。这也正是 LangGraph 区别于"调 API + 手写循环"的价值点。

### Q3：评估集怎么设计的？为什么危险漏报率是核心指标？

答：评估集是 35 个"症状 + 故障码 → 标准安全等级"的用例，覆盖海尔/美的/西门子三个品牌 × 绿/黄/红三级，每条标注理由。核心指标是**危险漏报率**（本该判 red 却被判成 green/yellow 的比例）——因为这个场景下"漏报危险"远比"误报保守"严重，安全产品的底线是这个数必须为 0。我的结果稳定为 0，安全等级准确率约 90%。

### Q4：RAG 为什么选 BGE 本地 embedding？

答：两个原因：一是**中文效果**，BGE 是中文检索的标杆开源模型；二是**零成本 + 可离线**，本地跑不依赖 embedding API。而且我的项目 LLM 走 DeepSeek（国内直连），embedding 用本地 BGE，整体架构对国内网络友好。代码里 embedding 做了可配置抽象，换别的模型不改业务代码。

### Q5：印象最深的坑？

答：几个都挺典型——(1) Milvus Lite 在 Windows 不支持嵌入式 .db，报 Illegal uri，改成 gRPC server 模式解决；(2) 批量入库时 gRPC keepalive 被服务端掐断报 "too many pings"，靠"embedding 完成后再连库 + 分批 insert"解决；(3) mcp 2.x 把 FastMCP 改名为 MCPServer、API 大改，锁 `mcp<2` 保持 v1 接口。这些都能体现真实工程调试经验。

## 三、演示建议

现场演示时，走一条完整链路最打动人：

1. 左侧加入一台家电（体现持久化）；
2. 选中它，输入一个**开放式症状**（如"压缩机嗡嗡几秒就停，反复循环"），展示多轮追问；
3. 最终诊断报告卡的**安全等级色块 + 安全审查意见**；
4. 补一句"这是真实 LLM 诊断，不是写死的 mock"，并当场跑 `backend/eval/run_eval.py` 展示评估指标。
